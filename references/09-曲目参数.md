## 为什么这行的数是 110，而脚本会报 111.25

同一文件，不同测法：

| 方法 | 结果 | 可信度 |
|---|---|---|
| `analyze_music.py` 全频段自相关 | 111.25 BPM / 首拍 0.372 | ✗ 伪拍 |
| 其它自相关峰 | 112.35 – 112.75 | ✗ 伪拍 |
| `check_tempo.py` 低频段（20–150Hz）90 s 基线 | **110.00**，z_low **2.05**（次优 111.33 仅 1.44） | ✓ |
| 同上，150 s 基线 | **110.00**，z_low **1.68**（次优 110.80 仅 1.28），中位偏移 −3 ms | ✓ |

结论：这支曲子音头密集（约 4.9 个/秒），全频段 onset 会锁到附近的伪拍；**只有低频段 + 长基线能稳定定到 110**。

## 用法

```ts
export const BPM = 110;
export const BEAT_F = 60 / BPM * 30;   // 16.364
export const FIRST_BEAT_F = 0.348 * 30; // 10.44
export const beat = (n: number) => FIRST_BEAT_F + n * BEAT_F;
```

## A Rusty Dream 的额外说明（2026-11-18）

- 这支曲子的**节拍层是小节级**：主歌 4 s 一句（2 小节），副歌 2 s 一句（1 小节）。
  `check_tempo.py` 用 t1=1.61 / t2=141.61 / N=70 复核得到 **period 2.0000 s、z_all 1.79、z_low 1.01、中位偏移 −129 ms**，
