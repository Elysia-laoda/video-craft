# 01 做视频：从音乐到成片

## 1 量音乐（半小时内必须做完）

```powershell
python templates/验收脚本/analyze_music.py <音频路径> [fps]   # fps 默认 30
```

输出四件事，全部写进代码常量：

- **BPM**（onset 包络自相关，60–200 扫）
- **首拍偏移**（相位扫描，扫到能量最齐的相位）
- **每拍帧数** = 60 / BPM × fps（30fps 下 98.5 BPM → 18.274 帧）
- **逐 2s 电平**（dBFS）—— 用来找段落、找留白

```ts
export const BPM = 98.5;
export const BEAT_F = 60 / BPM * 30;   // 18.274
export const FIRST_BEAT_F = 0.499 * 30;
export const beat = (n: number) => FIRST_BEAT_F + n * BEAT_F;
```

> 踩过的坑：不要用 `ffmpeg -af astats` 之类的近似值；不要相信"感觉 100 BPM"。差 0.5 BPM，三分半的片子末尾就错 3 秒。

### 1.1 自动测速必须人工复核（强制）

全频段 onset + 自相关在**音头密集**的曲子上会锁到附近的伪拍。实测默认 BGM（`AI的小曲.mp3`）：

| 方法 | 结果 |
|---|---|
| 全频段自相关 | 111.25 BPM / 首拍 0.372s |
| 换一个相关峰 | 112.35 BPM |
| **低频段（20–150Hz，底鼓）+ 90s 基线 + N 搜索** | **110.00 BPM / 首拍 0.348s**（z_low 2.05，次优 111.33 只有 1.44） |
| 150s 基线复核 | 仍是 110.00（z_low 1.68，次优 110.80 仅 1.28；中位偏移 −3ms） |

已知曲目（含默认 BGM）直接抄 `09-曲目参数.md`，不用再测。

结论：**标称 BPM 不是重点，"网格能不能对上底鼓"才是**。所以必须做下面四步：

1. 找**两个相隔 ≥ 60–90 秒**的强音头 `t1`、`t2`（30 秒太短，几种拍速都能"对上"），数中间拍数 `N`。
2. 跑工具（会自动试 `N±2`，并分别给全频段与低频段的 z 分数）：
   ```powershell
   python templates/验收脚本/check_tempo.py <音频路径> <t1> <t2> <N>
   ```
3. 取**低频段 z_low 最高**的那一组；如果第一名和第二名差距 < 0.3，说明这段不干净，换一对音头重来。
4. **回代全片**：`beat(n) = t1 + n × period`，抽查 30s / 90s / 150s 的音头；中位偏移 > 50ms 就把 `t1` 按报告挪过去再写进代码。

> 只有在"低音鼓"不明显、或者本来就是自由节拍的曲子上，才退回纯听感数小节；这时把取值与理由写进项目 README，别让下一个人再猜。

## 2 写剧本（先结构，后句子）

- 先决定**时间结构**：倒叙开篇 / 三幕 / 章节体 / 单线。结构决定第一帧给什么。
- 再写**逐段任务**：每段一句话说"这一段要让观众知道什么"。
- 最后才是**画面上的字**：一句话 ≤ 24 字，能拆成两行就拆。
- 剧本里给每个段落标**绝对时间**，后面节拍表直接抄。

## 3 写节拍表（帧号必须算）

每段一行：`段 | 时间 | 帧 | 画面 | 动作 | 字幕 | 音效`。
帧号 = 秒 × fps，写死在表格里，代码里照抄。**改时间段要同时改五处**：Sequence、字幕表、组件内部 start、剧本、节拍表。

## 4 搭 Remotion 工程

最小骨架见 `03-场景与工程.md`。三条规矩：

1. 一个段落一个组件，`<Sequence from={帧} durationInFrames={帧数}>` 排时间轴。
2. 组件内部只认 `useCurrentFrame()`，**禁止** CSS animation / transition / setTimeout。
3. 随机一律 `rnd(seed)`（mulberry32），否则每次渲染都不一样。

## 5 字幕 / 歌词层

- 固定在 `y 118–260`，场景主文字 `y ≥ 300`。
- 逐字显影：`opacity = 0.15 + 0.85 * clamp((local - i*0.035)/0.3)`。
- 颜色可以是时间函数（例如全片从红走到蓝）：`lyricColor(t) = lerp(红, 蓝, t/总时长)`。
- 底下垫一层 `radial-gradient` 暗底（0.6 不透明度、300px 高），保证压在任何画面上都能读。
- 单行 62px、双行 52px、楷体、字距 0.18em 是实测舒服的一组。

## 6 声音

| 层 | 做法 | 注意 |
|---|---|---|
| BGM | 整段 mp3，`<Audio volume={0.9}>` | 不要用 `loop` + 音量回调（实测不生效） |
| 旁白 | 先合成、量真实时长、再回算锚点 | TTS 常比估算长 0.3–0.5s |
| 音效 | 少量代码合成（撞击/翻页/雨） | 卡在拍上，别铺满；真实录音见 `08-音效与素材.md` |

要"静音窗"时，音乐、底噪、音效尾巴三样一起压；只静音音乐必漏。

## 7 渲染

```powershell
# 探针：先渲 5–10 秒
npx remotion render src/index.ts <CompId> out/probe.mp4 --frames=1000-1300 --concurrency=4
# 全片
npx remotion render src/index.ts <CompId> out/film.mp4 --concurrency=4 --crf=20
```

- **并发别贪**：16 核机器用 8 也可能在长片里崩（子进程异常退出），4 稳。
- 崩了先看输出尾部有没有 `ChildProcess` / `spawn` 字样；重跑同一命令即可，Remotion 会重新打包。
- 首帧会自动下载 chrome-headless-shell（约 113MB），**缓存在工程内 `node_modules/.remotion/chrome-headless-shell`**（不是 `%LOCALAPPDATA%\remotion`）；国内可能失败，失败就 `--browser-executable` 指向本机 chrome-headless-shell。
